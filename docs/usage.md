# 使用指南

[返回项目介绍](../README.md)

## 连接前准备

已验证 DSH **0.2.2-rc.1**，面向 Windows 桌面客户端；插件 **0.2.6** 另在 Windows 本机的独立 `web` profile 中验证了 WSL 全量文件浏览、轻量 / 全量切换、断开与重连。先确认你安装插件的 profile 与实际启动客户端使用的 profile 一致。

| 连接方式 | 必要准备 |
| --- | --- |
| WSL 轻量 | Windows 已安装并可启动 WSL 发行版；发行版中有 Python 3、Bash，Windows 可访问其共享目录 |
| WSL 全量 | 发行版中有 Python 3、Bash；首次部署可访问 npm 和 Node 下载源 |
| SSH 轻量 | 系统 OpenSSH 可登录；远端有 Python 3、Bash；项目目录已有 SSHFS 挂载 |
| SSH 全量 | 系统 OpenSSH 可登录；远端为 Linux，有 Python 3、Bash；首次部署可访问 npm 和 Node 下载源 |

如果远端已经有 Node **24.9+**，全量部署会复用它；否则自动下载并校验 Node。自动下载支持 Linux x64 / arm64，不需要 root。

## 选择运行模式

选 **轻量模式**，如果你希望继续使用本机的模型配置，只把项目文件和 Bash 命令放到远端。每条远程命令独立执行，不提供持续存在的交互终端。

选 **全量模式**，如果你希望项目由远端 DSH 完整运行，并使用其原生终端、后台任务、PTC 或子代理。可用的模型、工具和插件由远端 DSH 决定。

首次添加时默认选择全量模式；SSH 和 WSL 表单会分别保留本次打开客户端期间选择的模式。后续可在保存项目的「连接设置」中重新选择。

## 添加 WSL 项目

1. 在侧栏打开「远程工作区」，选择 **WSL**。
2. 选择发行版；没有看到预期条目时点击「刷新列表」。
3. 选择运行模式，按需填写用户名。留空使用发行版的默认用户。
4. 在「远程项目目录」中填写 Linux 绝对路径。路径必须已存在，不能填写 Windows 的 `C:\...` 路径。
5. 点击「浏览目录」可以进入子目录或返回上一级。浏览器当前显示的目录就是即将添加的项目目录。
6. 点击「测试连接」确认目标可访问。测试连接只检查连接与目录，不代表已完成全量后端部署。
7. 按需填写工作区名称，点击「添加到工作区」。全量模式首次连接可能需要数分钟。
8. 在已保存的卡片中点击「打开」。以后从原生侧栏选择项目下的会话即可继续工作。

WSL 两种模式均直接调用发行版，不需要在 WSL 中额外启用 SSH 服务。轻量模式通过 Windows 的 WSL 目录共享访问文件，受共享身份和文件权限约束；全量模式直接使用远端文件接口。

## 添加 SSH 项目

### 先确认系统 SSH 可登录

在终端连接一次并核对主机指纹，例如：

```sh
ssh -p 22 dev@your-server.example
```

使用配置别名时：

```sh
ssh dev-server
```

插件不会弹出首次主机指纹确认，也不会关闭主机密钥检查。指纹改变时，先确认服务器变更的原因，再由你更新 OpenSSH 的记录。

### 填写连接信息

「主机或 SSH 别名」只填写主机名、IP 或 `~/.ssh/config` 的 Host 别名；用户名和端口分别填写。使用别名时，配置文件已有的用户名和端口可留空沿用。

「远程项目目录」使用绝对路径，例如 `/home/dev/projects/demo`。选择运行模式和登录方式后，测试连接，再添加项目。

### 选择登录方式

| 方式 | 填写内容 | 说明 |
| --- | --- | --- |
| 自动选择 | 主机 / 别名，按需填写用户名、端口和密码 | 使用系统 OpenSSH 配置、默认私钥、ssh-agent 及服务器允许的认证方式 |
| 仅密码 | SSH 登录密码 | 只尝试 password 认证，不尝试公钥和键盘交互认证 |
| 密钥 | 本机私钥文件路径；加密时填写私钥口令 | 桌面版可点击「选择密钥文件」，也支持 `~/.ssh/id_ed25519` |
| 证书 | OpenSSH 用户证书与配套私钥；按需填写口令 | 通常为 `id_ed25519-cert.pub`，服务器需信任签发该证书的 SSH CA |

密钥应选择 **OpenSSH 私钥**，而不是 `.pub` 公钥。PuTTY `.ppk` 需要先转换格式。这里的证书是 OpenSSH 用户证书，不是 HTTPS / X.509 证书。

已将加密私钥加入本机 ssh-agent 时，可以不填私钥口令。Windows OpenSSH 拒绝权限过宽的私钥时，需自行限制文件访问权限；插件不自动修改私钥 ACL。

密码与口令不会写入连接记录，重启本机 DSH 进程后需要重新提供。对已保存的项目，点击「连接设置」，填写凭据，再点击「连接此模式」。密钥和证书只记录文件路径，应保证文件仍在原位置。

### 轻量 SSH 的文件挂载

轻量模式分别通过 SSHFS 访问文件、通过系统 OpenSSH 执行命令。因此，**命令登录成功，不代表文件挂载也已配置好**。

Windows 可使用 [WinFsp](https://github.com/winfsp/winfsp) 和 [SSHFS-Win](https://github.com/winfsp/sshfs-win)。先把整个远程项目目录挂载到本机，再将挂载目录填写到「本机 SSHFS 挂载路径」，例如 `Z:\demo`。

- 挂载内容必须与表单填写的整个远程项目目录一致。
- 该字段不能只是一个普通的空目录。插件会用临时校验文件检查两边是否指向同一目录。
- 指定密码、密钥或证书时，先使用同一凭据建立挂载；表单中的凭据不会自动传给 SSHFS。
- Windows 的「自动选择」允许留空，使用 SSHFS-Win 的绝对路径共享；复杂别名、跳板机、IPv6 或带口令私钥建议使用预先建立的挂载。
- macOS / Linux 本机需要显式填写已经建立的挂载路径，此组合尚未实机验证。

如果不希望管理 SSHFS 挂载，选择全量模式，直接使用远端文件系统。

## 全量模式准备

全量模式首次添加项目时，在远端当前用户目录 `~/.local/share/dsh-ssh-workspaces/` 中安装与客户端协议匹配的 DSH。安装通常需要数分钟，后续连接会复用安装和已有后端。

远端 DSH 使用自己的 `~/.dsh` 模型与插件配置。**本机 API Key、账号凭据和第三方插件不会自动同步。**

如果远端已经使用过 DSH，可继续使用该用户的现有配置。如果尚未配置模型，可以从远端终端运行已部署的 DSH CLI，并按提示添加模型提供方：

```sh
# 当前插件部署的版本；升级后以实际安装目录为准。
~/.local/share/dsh-ssh-workspaces/dsh-0.2.2-rc.1/node_modules/.bin/dsh
```

如果系统没有可用的 Node，先将插件安装的 Node 加入当前终端的 PATH。根据机器架构选择 `x64` 或 `arm64`：

```sh
export PATH="$HOME/.local/share/dsh-ssh-workspaces/node-v24.12.0-linux-x64/bin:$PATH"
```

配置的具体选项以 [DeepSeek Harness 文档](https://github.com/deepseek-ai/deepseek-harness) 和 CLI 提示为准。不要把 API Key 写入项目文件、Issue 或公开截图。

后端只监听远端 `127.0.0.1` 的随机端口，通过 SSH / WSL 通道连接，通常无需在服务器开放额外入站端口。

## 已保存项目与模式切换

### 打开与继续会话

卡片中的 **打开** 会为该项目新建会话。继续之前的工作，请从侧栏该项目下选择原会话，而不是反复点击「打开」。

侧栏标题旁的远程图标会显示连接状态；悬停可以查看目标主机 / 发行版及模式。状态定期更新，故障发生到图标变化之间可能有短暂延迟。

### 后续切换轻量 / 全量

1. 在「远程工作区」中找到已保存的项目。
2. 点击「连接设置」，在「连接模式」中选择另一模式。
3. 按需补充密码、口令或轻量 SSH 挂载路径。
4. 点击「以轻量模式连接」或「以全量模式连接」。

切换成功后，已有的对应模式工作区会被复用；不存在时创建该模式的独立入口。两个模式指向同一远程目录，**文件共享，历史分别保留**。原来的入口、对话和运行位置不会改变，切换失败也不会移除原模式。

切回原模式后，从它的侧栏入口打开原会话即可继续。需要暂停原模式连接时，单独点击「断开」。

### 断开与重新连接

| 操作 | 结果 |
| --- | --- |
| 轻量断开 | 停止插件的远程命令通道，取消正在执行的插件命令，并阻止该项目继续调用文件或命令工具；保留挂载、登记与历史 |
| 全量断开 | 关闭本机隧道，远端 DSH 与后台任务继续运行；共用同一后端的全量项目会一起离线 |
| 连接 / 重新连接 | 恢复连接；重启后缺少密码或口令时，先在「连接设置」中补充 |
| 移除登记 | 撤下该模式的项目入口，保留文件、历史和旧会话路由；不是卸载远端 DSH，也不是删除项目 |

主动断开会被保存。状态轮询或重启客户端不会自动连回；临时网络故障的事件订阅可以重试，但不会自动重新发送提示词或重复执行工具调用。

关闭客户端、断开连接和移除登记都不会停止远端 DSH。需要停止远端后端或任务时，应在远端自行管理。

## 常见问题

### 安装后找不到「远程工作区」

先重启客户端，确认插件安装到了实际使用的 profile。官方桌面版通常是 `desktop`，普通 `dsh web` 是 `web`；安装到另一个 profile 不会在当前窗口生效。

如果手动隐藏过入口，可在侧栏「更多 → 编辑侧栏」中重新固定。仍然没有入口时，记录插件与 DSH 版本，并提供经过脱敏的加载错误。

### 测试连接成功，添加仍失败

测试只检查目标和目录。轻量 SSH 添加时还会验证挂载是否正确；全量添加时还会安装并启动后端。按报错分别检查挂载、远端系统依赖、下载网络、磁盘空间和目录权限。

### 重启后密码连接失败

密码和私钥口令只保留在当前客户端进程内。打开项目的「连接设置」，重新填写后连接。需要免填密码时，可使用系统 ssh-agent 或 OpenSSH 配置管理认证。

### 文件能打开，但 Agent 不能执行远程命令

检查项目是否已连接，以及轻量模式是否使用 Native 工具模式。轻量模式不支持原生终端、PTC、后台任务、子代理和 worktree；需要这些能力时选择全量模式。

### 全量模式看不到本机模型或插件

全量模式使用远端 DSH 的配置。先为远端添加模型提供方和需要的插件；它不会复制本机登录状态。

### 升级 DSH 后出现加载或接口错误

目前已验证 DSH `0.2.2-rc.1`。先确认版本与插件声明相符；不要只凭“最新版”判断兼容。反馈时提供准确版本和脱敏报错。

### 连接信息保存在什么位置

默认位于 DSH 数据目录下的 `ssh-workspaces.json` 与 `ssh-backends.json`。其中包含主机、路径、密钥路径和连接登记，仍属于本机配置，不建议公开。文件不保存 SSH 密码、私钥内容或远端认证 Cookie。

远端部署目录内的 `backend.json` 和 `backend.log` 可能包含启动令牌，不要直接上传原文件。底层路由及验证说明见[开发指南](development.md)。
