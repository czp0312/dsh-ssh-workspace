# 使用指南

[返回项目介绍](../README.md)

## 连接前准备

已验证 DSH **0.2.2-rc.1**，面向 Windows 桌面客户端；插件从 **0.3.1** 起已验证桌面全量项目侧栏显示，以及独立 `web` profile 的真实 WSL 全量连接。远端文件、终端、附件、断开重连、模式往返和原会话保留已通过独立 WSL 项目验证；Skill 选择性推送和远端技能发现已有实机验证。原生订阅热更新有真实 DSH 流监督器回归覆盖。Docker 已通过参数、身份、认证和 UI 测试，当前环境没有 Docker daemon，真实容器验收待补。**0.3.2** 进一步实测了环境分组、共享全量连接的断开与恢复、轻量项目不受共享断开影响，以及逐项目模式往返。先确认安装插件的 profile 与实际启动客户端一致。

| 连接方式 | 必要准备 |
| --- | --- |
| WSL 轻量 | Windows 已安装并可启动 WSL 发行版；发行版中有 Python 3、Bash，Windows 可访问其共享目录 |
| WSL 全量 | 发行版中有 Python 3、Bash；首次部署可访问 npm 和 Node 下载源 |
| SSH 轻量 | 系统 OpenSSH 可登录；远端有 Python 3、Bash；项目目录已有 SSHFS 挂载 |
| SSH 全量 | 系统 OpenSSH 可登录；远端为 Linux，有 Python 3、Bash；首次部署可访问 npm 和 Node 下载源 |
| Docker 轻量 | Docker CLI 可访问目标引擎；已有运行中的 Linux 容器，有 Python 3、Bash；项目目录与本机双向共享 |
| Docker 全量 | Docker CLI 可访问目标引擎；容器使用 glibc Linux，有 Python 3、Bash、可写 home；首次部署可访问下载源 |

如果远端已经有 Node **24.9+**，全量部署会复用它；否则自动下载并校验 Node。自动下载支持 Linux x64 / arm64，不需要 root。

## 选择运行模式

选 **轻量模式**，如果你希望继续使用本机的模型配置，只把项目文件和 Bash 命令放到远端。每条远程命令独立执行，不提供持续存在的交互终端。

选 **全量模式**，如果你希望项目由远端 DSH 完整运行，并使用其原生终端、后台任务、PTC 或子代理。可用的模型、工具和插件由远端 DSH 决定。

首次添加时默认选择全量模式；SSH、WSL 和 Docker 表单分别保留本次打开客户端期间选择的模式。后续可在项目行的「项目模式」中重新选择。**模式始终属于项目**，同一环境内可以同时有轻量和全量项目。

轻量模式沿用本机 DSH 已发现的技能。规范类 Skill 可用于远程项目；引用本机脚本、Windows 绝对路径、本机终端、PTC 或子代理的 Skill，需要按远程执行限制适配。全量模式读取远端自己的技能，可按下文的步骤同步本机 Skill。

## 添加 WSL 项目

1. 在侧栏打开「远程工作区」，点击「添加项目」，选择 **WSL**。没有已保存项目时直接显示添加表单。
2. 选择发行版；没有看到预期条目时点击「刷新列表」。
3. 选择运行模式，按需填写用户名。留空使用发行版的默认用户。
4. 在「远程项目目录」中填写 Linux 绝对路径。路径必须已存在，不能填写 Windows 的 `C:\...` 路径。
5. 点击「浏览目录」可以进入子目录或返回上一级。浏览器当前显示的目录就是即将添加的项目目录。
6. 点击「测试连接」确认目标可访问。测试连接只检查连接与目录，不代表已完成全量后端部署。
7. 按需填写工作区名称，点击「添加到工作区」。全量模式首次连接可能需要数分钟。
8. 添加成功后返回项目列表，点击项目行中的「打开项目」。以后从原生侧栏选择项目下的会话即可继续工作。

WSL 两种模式均直接调用发行版，不需要在 WSL 中额外启用 SSH 服务。轻量模式通过 Windows 的 WSL 目录共享访问文件，受共享身份和文件权限约束；全量模式直接使用远端文件接口。

## 添加 SSH 项目

### 先确认系统 SSH 可登录

在终端连接一次并核对主机指纹，例如：

```sh
ssh -p 22 dev@your-server.example
```

使用配置别名时：

```sh
ssh dev-server
```

插件不会弹出首次主机指纹确认，也不会关闭主机密钥检查。指纹改变时，先确认服务器变更的原因，再由你更新 OpenSSH 的记录。

### 填写连接信息

「主机或 SSH 别名」只填写主机名、IP 或 `~/.ssh/config` 的 Host 别名；用户名和端口分别填写。使用别名时，配置文件已有的用户名和端口可留空沿用。

「远程项目目录」使用绝对路径，例如 `/home/dev/projects/demo`。选择运行模式和登录方式后，测试连接，再添加项目。

### 选择登录方式

| 方式 | 填写内容 | 说明 |
| --- | --- | --- |
| 自动选择 | 主机 / 别名，按需填写用户名、端口和密码 | 使用系统 OpenSSH 配置、默认私钥、ssh-agent 及服务器允许的认证方式 |
| 仅密码 | SSH 登录密码 | 只尝试 password 认证，不尝试公钥和键盘交互认证 |
| 密钥 | 本机私钥文件路径；加密时填写私钥口令 | 桌面版可点击「选择密钥文件」，也支持 `~/.ssh/id_ed25519` |
| 证书 | OpenSSH 用户证书与配套私钥；按需填写口令 | 通常为 `id_ed25519-cert.pub`，服务器需信任签发该证书的 SSH CA |

密钥应选择 **OpenSSH 私钥**，而不是 `.pub` 公钥。PuTTY `.ppk` 需要先转换格式。这里的证书是 OpenSSH 用户证书，不是 HTTPS / X.509 证书。

已将加密私钥加入本机 ssh-agent 时，可以不填私钥口令。Windows OpenSSH 拒绝权限过宽的私钥时，需自行限制文件访问权限；插件不自动修改私钥 ACL。

密码与口令不会写入连接记录，重启本机 DSH 进程后需要重新提供。全量模式在「共享全量后端 → 更多 → 连接认证」中填写；轻量模式在项目的「项目模式」中填写，再点击「连接此模式」。密钥和证书只记录文件路径，应保证文件仍在原位置。

### 轻量 SSH 的文件挂载

轻量模式分别通过 SSHFS 访问文件、通过系统 OpenSSH 执行命令。因此，**命令登录成功，不代表文件挂载也已配置好**。

Windows 可使用 [WinFsp](https://github.com/winfsp/winfsp) 和 [SSHFS-Win](https://github.com/winfsp/sshfs-win)。先把整个远程项目目录挂载到本机，再将挂载目录填写到「本机 SSHFS 挂载路径」，例如 `Z:\demo`。

- 挂载内容必须与表单填写的整个远程项目目录一致。
- 该字段不能只是一个普通的空目录。插件会用临时校验文件检查两边是否指向同一目录。
- 指定密码、密钥或证书时，先使用同一凭据建立挂载；表单中的凭据不会自动传给 SSHFS。
- Windows 的「自动选择」允许留空，使用 SSHFS-Win 的绝对路径共享；复杂别名、跳板机、IPv6 或带口令私钥建议使用预先建立的挂载。
- macOS / Linux 本机需要显式填写已经建立的挂载路径，此组合尚未实机验证。

如果不希望管理 SSHFS 挂载，选择全量模式，直接使用远端文件系统。

## 添加 Docker 项目

在「远程工作区 → 添加项目」选择 **DOCKER**，有两种连接方式：

| Docker 所在位置 | 填写方式 |
| --- | --- |
| 本机 Docker / Docker Context | 本机需要可执行的 Docker CLI。Context 留空时使用 CLI 当前上下文；也可填写已配置的远程 Context 名称 |
| SSH 服务器上的 Docker | 填写宿主机 SSH 地址、端口、用户及登录方式；Docker CLI 在 SSH 宿主上执行。本机无需另装 Docker CLI |

SSH 宿主用户需要有访问 Docker daemon 的权限；插件不自动使用 `sudo`。容器内部不需要 sshd，也无需发布 DSH 的端口。

1. 选择 Docker 所在位置，填写必要的 Context 或 SSH 信息。
2. 点击 **读取容器**。列表显示运行中与已停止的容器，只有运行中的容器可选；也可直接填写名称或 ID。
3. 按需填写 **容器内用户**，留空沿用容器默认用户。支持用户名、UID 或 `UID:GID`；用户需要存在于容器的 passwd 数据中，并拥有可写 home。
4. 填写容器内已存在的项目绝对路径，例如 `/workspace/demo`，可以浏览目录。
5. 选择模式并测试。轻量模式填写 **本机共享/挂载路径**，例如容器 bind mount 的本机源目录；远端 Docker 则需要已有的文件挂载。插件会用临时校验文件确认两端实际共享同一目录，并清理校验文件。
6. 添加工作区。首次全量连接会在容器用户 home 内安装匹配的 DSH。

全量模式要求 glibc Linux；Alpine / musl 镜像不能使用当前自动部署的 Node，可用共享目录的轻量模式。容器需要具备 Python 3 和 Bash，插件不会自动修改镜像或安装这些系统依赖。

连接保存完整容器 ID；容器名只用于展示。同名容器重建后请移除旧登记、重新添加。连接操作不会启动已停止的容器，也不会自动创建、重建或删除容器。

断开全量连接只关闭本机通道，不停止容器或容器内 DSH。容器停止时其 DSH 与任务也停止；删除容器可能丢失未持久化的 home、配置与历史，请按自己的容器存储方案管理。

## 选择性同步本机 Skill

同步入口位于 **已连接的全量项目项目行 → 同步 Skill**，适用于 SSH、WSL 和 Docker。轻量模式直接使用本机 DSH 的技能，不需要复制指令到远端。

1. 点击「同步 Skill」，插件读取本机**默认 Agent 预设**可见的用户级与自定义技能，并比较远端用户技能目录。
2. 通过名称、描述或来源搜索，逐项勾选；默认仅勾选「远端缺少」的技能。「选择缺失项」选择全部缺失项，搜索不会自动取消已勾选项。
3. 「已一致」无需再次推送。「内容不同」默认不勾选；需要更新时先开启 **允许覆盖所选差异项**，再勾选要覆盖的技能。
4. 检查所选数量和大小，点击 **同步所选 N 项**。
5. 查看逐项结果，列表会重新比较并清空选择，不会自动勾选之前跳过的技能。失败项会显示原因，按原因处理后刷新、重新选择并重试。

目标是远端 DSH 用户技能目录，默认 `<DSH_HOME>/skills`，未设置 `DSH_HOME` 时为 `~/.dsh/skills`。界面可展开「查看远端保存路径」。同一远端用户的其他项目也可发现这些技能；远端项目级同名技能仍优先于用户级技能。

### 同步范围与保护

- **来源**：从 DSH 技能注册表读取默认预设中的 `user-dsh`、`user-agents` 和 `custom`，沿用 DSH 的同名优先级。不把 Codex 等工具目录自动当作 DSH 的目录；请先在 DSH 中配置需要的技能。
- **项目和内置技能**：项目级技能已属于项目，不参与此用户目录同步；随包、系统及插件运行时技能也不参与复制。
- **资源**：目录形式的 Skill 包含 `SKILL.md`、脚本和参考资料。单个 Markdown 形式的 Skill 只复制其指令，转成远端目录中的 `SKILL.md`，不会把本机同级目录的文件一并带走。
- **依赖与凭据**：不复制 `.env`、`.env.*`、`.git`、`node_modules` 或 `__pycache__`。不会安装 Python / npm 依赖、迁移 MCP、复制 API Key，或改写 Skill 正文中的系统路径。
- **更新**：只有明确选择并允许覆盖的条目才会替换。远端独有技能不删除；含上述本机数据目录的远端技能、资源符号链接、特殊文件，以及位于兼容目录或单文件中的同名技能，不自动覆盖，界面显示原因。
- **变化与断开**：本机内容或远端目录变化时需要重新比较；预览绑定本次连接，断开或重连后旧列表失效。同步不后台定时运行。
- **大小**：单项最多 10 MiB / 1024 个文件，指令文件最多 128 KiB；每批最多 128 项 / 20 MiB。超过批次限制时取消部分选择，分批同步。

DSH 将技能目录提供给模型，并按需加载正文。同步完成后可新建远程会话并明确要求使用对应 Skill；已有会话的目录刷新由远端 DSH 负责。技能能被加载与其中每个程序能运行是两回事，脚本依赖、执行权限及跨系统路径仍需匹配远端环境。

## 全量模式准备

全量模式首次添加项目时，在远端当前用户目录 `~/.local/share/dsh-ssh-workspaces/` 中安装与客户端协议匹配的 DSH。安装通常需要数分钟，后续连接会复用安装和已有后端。

远端 DSH 使用自己的 `~/.dsh` 模型与插件配置。**本机 API Key、账号凭据和第三方插件不会自动同步。**

如果远端已经使用过 DSH，可继续使用该用户的现有配置。如果尚未配置模型，可以从远端终端运行已部署的 DSH CLI，并按提示添加模型提供方：

```sh
# 当前插件部署的版本；升级后以实际安装目录为准。
~/.local/share/dsh-ssh-workspaces/dsh-0.2.2-rc.1/node_modules/.bin/dsh
```

如果系统没有可用的 Node，先将插件安装的 Node 加入当前终端的 PATH。根据机器架构选择 `x64` 或 `arm64`：

```sh
export PATH="$HOME/.local/share/dsh-ssh-workspaces/node-v24.12.0-linux-x64/bin:$PATH"
```

配置的具体选项以 [DeepSeek Harness 文档](https://github.com/deepseek-ai/deepseek-harness) 和 CLI 提示为准。不要把 API Key 写入项目文件、Issue 或公开截图。

后端只监听远端或容器内 `127.0.0.1` 的随机端口，通过 SSH / WSL / Docker exec 通道连接，通常无需开放额外入站端口。

## 已保存项目与模式切换

### 打开与继续会话

管理页默认展示「我的远程项目」。可搜索名称、设备或路径，或筛选轻量 / 全量、SSH / WSL / Docker 及未连接的项目。添加表单通过「添加项目」打开，返回列表时会清空密码与私钥口令输入。

在线项目行中的 **打开项目** 进入原生会话输入页，DSH 会复用可用的空白会话。继续之前的工作，请从侧栏该项目下选择原会话。打开失败会在列表中显示原因，不会自动新建本机会话。

目录按 WSL 发行版、SSH 地址 / 端口或 Docker 容器归入可折叠的环境父项。环境中只有一份项目列表，各行保留自己的模式和操作。环境归组只影响管理页，原生侧栏仍沿用 DSH 的工作区组织方式。

**全量项目**通过环境内的「共享全量后端」统一连接和断开；多个实际后端分别显示，并注明各自影响的项目。**轻量项目**仍在项目行独立连接、断开。连通后显示「打开项目」，「移除登记」始终针对单个项目模式，位于项目的「更多」中。

连接区域会列出完整影响范围，搜索或筛选不会缩小断开范围；隐藏了受影响项目时会额外提示。部分项目在线、部分离线时，环境显示黄色「部分连接」，每个项目仍显示自己的真实状态。

全量模式同时检查后端连通性和远端项目登记。若目录已在另一端的 DSH 中移除登记，项目行显示异常，并提供 **重新添加目录**。点击后会预填原目录和名称，检查后点击「添加到工作区」恢复入口。旧会话由远端 DSH 保留，不自动迁移到新登记；原目录的文件不变。普通重连不会擅自重建已移除的登记。

侧栏标题旁的远程图标会显示连接状态；悬停可以查看目标主机 / 发行版及模式。状态定期更新，故障发生到图标变化之间可能有短暂延迟。

### 在同一设备添加另一个目录

在环境标题旁点击「添加项目」。表单会以一个现有项目为起点复用目标和认证方式，目录从其父目录开始选择；新项目仍可独立选择模式。同一环境存在多个连接身份时，也可从对应「共享全量后端 → 更多 → 使用此连接添加项目」进入。密码和私钥口令不会复制到表单；按需重新提供。轻量 SSH / Docker 要为新目录填写相应的共享路径。全量项目仅在实际后端身份一致时共用连接。

### 后续切换轻量 / 全量

1. 在「远程工作区」中找到已保存的项目。
2. 点击该项目的「项目模式」，在「此项目的运行模式」中选择另一模式。
3. 按需补充密码、口令或轻量 SSH 挂载路径。
4. 点击「以轻量模式连接」或「以全量模式连接」。

切换成功后，已有的对应模式工作区会被复用；不存在时创建该模式的独立入口。两个模式指向同一远程目录，**文件共享，历史分别保留**。原来的入口、对话和运行位置不会改变，切换失败也不会移除原模式。同一环境中的其他项目保持原模式；切到已存在的全量入口时复用健康连接，不强制重连共享后端。如果该共享后端原本已断开，恢复连接会让使用它的其他全量项目也重新在线，但不会改变任何项目的模式。

切回原模式后，从它的侧栏入口打开原会话即可继续。需要暂停轻量入口时，在该项目行点击「断开」；需要断开全量时，在共享后端区域操作，先检查列出的影响范围。

### 断开与重新连接

| 操作 | 结果 |
| --- | --- |
| 轻量断开 | 停止插件的远程命令通道，取消正在执行的插件命令，并阻止该项目继续调用文件或命令工具；保留挂载、登记与历史 |
| 全量断开 | 关闭本机隧道，远端 DSH 与后台任务继续运行；共用同一后端的全量项目会一起离线 |
| 全量连接 / 重新连接 | 「连接」复用健康后端；「更多 → 重新连接」显式重建共享通道；缺少凭据时进入同区域的「连接认证」 |
| 轻量连接 / 重新连接 | 恢复该项目的独立连接；重启后缺少密码或口令时，在「项目模式」中补充 |
| 移除登记 | 撤下该模式的项目入口，保留文件、历史和旧会话路由；不是卸载远端 DSH，也不是删除项目 |

主动断开会被保存。状态轮询或重启客户端不会自动连回；临时网络故障的事件订阅可以重试，但不会自动重新发送提示词或重复执行工具调用。

关闭客户端、断开连接和移除登记都不会停止远端 DSH。需要停止远端后端或任务时，应在远端自行管理。

## 常见问题

### 安装后找不到「远程工作区」

先重启客户端，确认插件安装到了实际使用的 profile。官方桌面版通常是 `desktop`，普通 `dsh web` 是 `web`；安装到另一个 profile 不会在当前窗口生效。

如果手动隐藏过入口，可在侧栏「更多 → 编辑侧栏」中重新固定。仍然没有入口时，记录插件与 DSH 版本，并提供经过脱敏的加载错误。

### 测试连接成功，添加仍失败

测试只检查目标和目录。轻量 SSH 添加时还会验证挂载是否正确；全量添加时还会安装并启动后端。按报错分别检查挂载、远端系统依赖、下载网络、磁盘空间和目录权限。

### 全量已连接，但侧栏没有项目

升级到 0.3.2（原生订阅修复自 0.3.1 提供），并在升级后重新加载客户端界面一次。旧版本在插件热更新时可能停止原生目录订阅；新版本把路由替换作为可恢复的连接变化处理。无需移除登记或重新安装远端 DSH。项目没有会话时也应显示；断开后目录保留并显示灰色标记。

如果仍然缺少，先清除侧栏搜索，检查是否使用工作区分组视图，并提供插件版本、DSH 版本和脱敏后的错误信息。

### 重启后密码连接失败

密码和私钥口令只保留在当前客户端进程内。全量模式从共享后端的「更多 → 连接认证」重新填写，轻量模式从项目的「项目模式」重新填写。需要免填密码时，可使用系统 ssh-agent 或 OpenSSH 配置管理认证。

### 文件能打开，但 Agent 不能执行远程命令

检查项目是否已连接，以及轻量模式是否使用 Native 工具模式。轻量模式不支持原生终端、PTC、后台任务、子代理和 worktree；需要这些能力时选择全量模式。

### 全量模式看不到本机模型或插件

全量模式使用远端 DSH 的配置。先为远端添加模型提供方和需要的插件；它不会复制本机登录状态。

### 升级 DSH 后出现加载或接口错误

目前已验证 DSH `0.2.2-rc.1`。先确认版本与插件声明相符；不要只凭“最新版”判断兼容。反馈时提供准确版本和脱敏报错。

### 连接信息保存在什么位置

默认位于 DSH 数据目录下的 `ssh-workspaces.json` 与 `ssh-backends.json`。其中包含主机、路径、密钥路径和连接登记，仍属于本机配置，不建议公开。文件不保存 SSH 密码、私钥内容或远端认证 Cookie。

远端部署目录内的 `backend.json` 和 `backend.log` 可能包含启动令牌，不要直接上传原文件。底层路由及验证说明见[开发指南](development.md)。
