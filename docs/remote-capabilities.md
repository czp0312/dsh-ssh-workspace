# 远程能力对照

本项目参考 ZCode 的同窗远程工作区体验，使用 DSH 自己的插件与会话机制实现。下面列出当前能力，避免把交互参考理解为全部功能已一一复刻。

| 能力 | 本项目 0.3.2 |
| --- | --- |
| 当前窗口、原生项目侧栏 | 已接入；空项目也显示，图标区分连接状态；已修复插件热更新导致原生订阅终止的问题 |
| 项目与连接管理 | 环境父项下统一列出目录，各项目独立选择模式；实际共享全量后端统一连接/断开，轻量连接独立；搜索仍显示完整影响范围；失效目录不阻止同组其他项目恢复 |
| 模式切换隔离 | 仅为当前项目创建或复用另一模式入口；保留原历史，其他项目模式不变；复用健康全量连接时不强制重连 |
| SSH / WSL | 已实现轻量与全量两种模式 |
| Docker | 已实现本机 / Context / SSH 宿主连接；保留两种模式，真实 daemon 验收待补 |
| 远端 Agent、文件与终端 | 全量模式转发到版本匹配的远端 DSH |
| 原生任务、PTC、子代理 | 全量模式使用远端 DSH 提供的能力与配置 |
| 本机 Skill 选择性同步 | 已实现选择、搜索、差异预览与显式更新；真实 DSH / WSL 已验证发现同步后的技能 |
| 轻量模式沿用本机 Agent | 本项目特色；不安装远端 DSH，沿用本机模型与可见技能 |
| 模型提供方自动下发 | 未实现；全量模式使用远端自己的配置 |
| MCP、插件、子代理配置、命令与钩子同步 | 未实现统一同步；需在远端 DSH 单独配置 |
| 会话跨模式迁移 | 不迁移；两种模式分别保留原工作区和历史 |
| 自动/定时同步技能 | 未实现；按用户选择显式推送，修改后重新比较 |

轻量模式能加载本机 Skill 的指令，但执行项目命令时仍在远端运行；引用本机脚本、Windows 路径或本机终端能力的 Skill 需要适配。全量模式把所选技能复制给远端 Agent，运行脚本所需的程序、依赖和权限仍由远端提供。

全量模式的核心路径是「添加远程目录 → 原生侧栏 → 原生会话、文件、终端和任务」。轻量模式则保留本机的模型和技能环境，省去远端 DSH 的部署与运行开销，适合 WSL、已有文件挂载及资源有限的主机。模式选择决定执行位置，不只是界面偏好；切换前会说明配置归属，原入口和历史保留。

0.3.1 已在 Windows DSH 0.2.2-rc.1 客户端验证全量项目显示，并在独立 profile 中验证 WSL 全量/轻量连接、同设备第二个项目动态加入侧栏。独立 WSL 项目还验证了远端文件、交互终端、二进制附件上传下载、断开重连及全量 → 轻量 → 全量后原会话保留。原生流恢复使用真实 DSH `RemoteStream` 回归验证。Docker 尚缺真实 daemon 验收；已实现的路由也不代表每一种远端插件、模型和任务组合都已实测。

0.3.2 在独立 DSH / WSL 环境中验证了同环境混合模式列表、共享全量断开与恢复、轻量状态隔离、模式往返保留原会话、筛选后的完整影响提示、折叠和窄布局。

ZCode 的远程配置同步参考：[数据同步说明](https://github.com/zai-org/ZCode/blob/main/docs/remote/data-sync.md)。该文件是一份设计规格，不能把其中每一项都当成 ZCode 已发布且经过验证的功能。本项目目前没有统一下发模型提供方、MCP、插件、子代理配置、命令与钩子；这些仍由远端 DSH 管理。本表描述的是当前交付范围，而非全部功能已经一一对齐。
